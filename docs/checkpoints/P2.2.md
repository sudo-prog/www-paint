# P2.2 — Layer-aware generation, scoring & paint order

**Date:** 2026-11-11 · Agent: BE (ThinkPad) · Status: **generation + paint
order done & verified; layer-aware SCORING not addressed**

---

## 1. Goal (roadmap 2.2)

> Layer-aware generation, scoring, paint order — *different style per layer on
> one image*.

## 2. Research / design

The renderer dispatches each shape on **its own** `shape.style`
(`Renderer.drawShapeAt` → `this._styles[shape.style]`). A `layer.style` field
alone is therefore inert. Two consequences the codebase already carried:

- `app.js`'s `layer-style-change` handler set `layer.style` and did nothing
  else — a comment there called the style dropdown a no-op until regenerate.
- Multi-layer generation assigned shapes to tonal bands
  (`background / shadows / outline / midtone / highlights`) but had no way to
  give a band its own style.

So 2.2 needs two pure operations plus one live-apply method:

| Piece | What it does |
|---|---|
| `resolveLayerStyles(spec)` | normalise `undefined` / `'ink'` / `{band:style}` / `Map` → `Record\|null`; `null` = no-op so non-opted-in callers stay byte-identical |
| `applyLayerStyles(shapes, spec)` | restamp each shape's `.style` by its band (`layerName`, else numeric `layer`) |
| `preserveLayerProps(fresh, prev)` | carry `visible/opacity/blendMode/style/locked` across a regenerate by `_name` |
| `engine.setLayerStyle(id, style)` | set `layer.style` **and** restamp the layer's existing strokes, so the change renders immediately |

New module `js/engine/layer-styles.js` (pure, node-testable). Wired into
`engine.generate()` (both the worker and Painter paths) and `app.js`'s
`layer-style-change` handler. Paint order is the renderer's existing
layer-id-sorted composite.

## 4. Correction — an earlier "broken composite" reading was WRONG

While probing I first concluded that `renderer.renderAll()`'s multi-layer branch
painted only the first band canvas. **That was a false alarm.** It came from the
per-band styles used in that run (`ink`/`pencil`/`charcoal`, which drew 0 ink in
the bare-engine probe), which made later bands *look* empty and made a
visibility toggle look inert. A decisive run with a uniform style shows the
composite is healthy — every band canvas is painted and per-layer visibility is
honoured (numbers in §3). This is now a standing assertion in the probe.

## 5. Follow-up (small, not a blocker)

In a **bare** engine (imported directly, no app shell) some styles
(`pencil`, `ink`, `charcoal`) drew **0 ink** on the plain canvas in one run
while `watercolor` drew normally; the same styles render fine in the project's
own harness. Likely tied to `_convertShape` stamping `seed: this._seed` (a
**number**, `0x1337BEEF`) onto every shape, which the style RNGs consume
(`rngFor(shape.seed || …)`). Worth a short check against the official harness
before deciding whether it is real. Recorded here, not claimed as a defect.

## 6. Not done — layer-aware *scoring*

2.2's "scoring" third is unaddressed: the Painter's scorer is not layer-aware
(no per-band residual weighting). Deferred; note it when 2.2 is revisited.
