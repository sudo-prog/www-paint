# P2.2m — Multi-layer generation on the MODULAR engine (layer bands)

**Date:** 2026-11-18 · Agent: BE (ThinkPad) · Status: **done — all gates green**

## 1. What was asked

User directive: *"Can you extract that and add to modular engine pls — it's a
key component of our app"* (the image→layer split). The split is **our own
feature**, not a Code Paint one — Code Paint has no layers; the legacy
`painter.js` merely carried the first implementation.

## 2. What was built

The layer system already existed as **our design** — `js/engine/masks.js`
(Phase 2.1, the soft tonal bands: background / shadows / midtones /
highlights, a partition-of-unity over luminance, the Zorn/Reilly value
abstraction). The Painter's `_assignLayer` was only a hard-threshold sketch
(`lum < 0.3 → shadows`, `> 0.7 → highlights`). So the extraction ported the
**capability** onto the modular engine using OUR masks, not the Painter's
thresholds:

| File | Change |
|---|---|
| `js/engine/modular-bridge.js` | NEW exports `bandAt()` + `classifyShapeBands()`; `buildModularPlan` gains **`layerBands: 'bands'`** (opt-in): every shape is stamped `layerName` = the masks.js band owning its anchor; outline strokes pinned to `'outline'`; plan returns `layerBands` + `bandCounts` |
| `js/engine/engine.js` | the modular branch in `generate()` now handles `multiLayer`: builds the five named band layers via `_initMultiLayerLayers()` + `preserveLayerProps`, sorts shapes by `layerName`, `renderer.multiLayer = true`. The `modular && !multiLayer` gate is gone |
| `tests/layer-bands.test.js` | NEW — 13 tests (opt-in purity, canonical names, band-follows-image, determinism, styles-through-bands) |
| `scripts/layer-bands-probe.cjs` | NEW — headless app-path probe, 12 assertions |
| `scripts/modular-switch-probe.cjs` | one STALE assertion fixed: still asserted `default settings.modular === false`, contradicting the shipped default flip (`5b52357`, ROADMAP_STATUS R6) |

Deliberate deviation from painter.js's `_assignLayer`: the Painter's
"first ~5% of emissions → background" progress rule is NOT carried over — the
optimiser emits coarse→fine, not background→detail, so band membership comes
from the IMAGE only (asserted by a dedicated test).
