# Checkpoint S7 — Worker automation path (Phase 6 engine half)

**Date:** 2026-11-17 · Agent: BE (ThinkPad) · Track-S **S7** (= BE **B5**)
**Exit criteria:** *"Batch of N images completes with a deterministic result per
image; cancel mid-run is clean; same `(profile, seed, image-hash)` → bit-identical
PNG."*

---

## 1. What was missing

`js/engine/worker.js` was the **pre-R1** module — it drove
`generateCandidates`/`scorer.js` (the retired generator path), had **no importer**
anywhere in the app, and knew nothing about a Style Profile, a re-bake guarantee,
batch mode, or a working cancel. Phase 6's engine half was therefore open, and the
`(profile, image | imageBatch, seed?) → { result, score, strokes }` contract
(Track S §3, S7) had no implementation.

## 2. What shipped

### `js/engine/bake.js` (NEW — pure, node-testable)

The deterministic automation core, on the **engine of record** (`optimizer.js`):

| Export | Role |
|---|---|
| `contentHash(pixels, w, h)` | A strided FNV-1a 32-bit content hash (8 hex chars) — the image half of the re-bake key. Cost is size-independent (samples ≤ ~64 KiB) yet content-sensitive. |
| `contentDigest({seed, imageHash, shapes})` | Pins a bake: hashes the seed, the image hash and every shape (type/params/colours/alpha/style/layer/order) **in emitted order**. |
| `bakeImage(profile, image, opts)` | One bake → `{ shapes, count, imageHash, digest, score, options, stats }`. `profileToOptimiserOptions` maps the profile; `seed` defaults to `BAKE_DEFAULTS.seed`; `score:false` skips the (independent-raster) `simMae` measurement. |
| `runBakeBatch(jobs, opts)` | Sequential batch with `onProgress` (index `-1` at start, then per job) and a `shouldCancel()` polled before every job → `{ results, total, completed, cancelled }`. |

### `js/engine/worker.js` (REWRITTEN — the worker host)

Now a thin host over `bake.js`:

- `{type:'bake', id, profile, seed, jobs:[{id,pixels,width,height}], bake?}` →
  streams `progress` + a `result` per job, then `complete {cancelled, completed, total}`.
- `{type:'cancel', id}` sets a per-batch cancel flag.

**Cancellability fix (the one real trap).** A worker's message loop is blocked
while it computes, so a synchronous batch can never *receive* a `cancel`: the
first draft's cancel test could not have worked. The loop now bakes **one job then
yields to the event loop** (`setTimeout 0`) before the next, so a queued `cancel`
is delivered between jobs and the batch stops cleanly. Measured: a 6-job batch
cancelled at index 0 stops at **2 completed**.

`scripts/bake-probe.cjs` drives the **real module worker** (`new Worker('/js/engine/worker.js',
{type:'module'})`) and re-exports the PNG from a **fresh engine** each run, so the
bit-identity check is the actual Phase-6 criterion, not a shape comparison.

## 4. Honest scope

- "Strokes" in the S7 contract is `bake.js`'s `shapes`; the PNG half is the
  caller's `engine.exportPNG()` on them (a canvas concern, kept out of the pure core).
- The batch's per-job seed is `seed + i` — each image is independent yet
  reproducible; re-running the same batch reproduces every digest.
- No render path was touched (`bake.js` is new, `worker.js` had no importer), so
  the 9 pinned baselines cannot move — verified anyway.
