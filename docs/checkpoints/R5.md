## 1. What R5 asks for, and the one thing this note does NOT claim

`docs/CLEANROOM.md` §4 defines R5 as *"**Exceed** — per-layer styles,
smudge/blend + impasto, wet media, Style Profiles, AI refinement (roadmap Phases
2–5) — features the reference does not have"*, with the exit criterion (from
`HANDOFF-BE.md` B4) *"the exceed list demonstrably beats the port on the bench"*.

**Honest deviation, stated first.** That exit criterion cannot be satisfied *as
written*, because the bench (`scripts/parity-bench.cjs`) measures **content
fidelity on four images**, and the exceed list is a set of **capabilities** — the
reference worker has no layer stack, no wet-media model and no profile, so there
is nothing on its side to compare those against. Measuring "the capability beats
the reference" would need a bench that renders through the app's own renderer.

What this note therefore records, honestly:

1. a **capability matrix** — every R5 item, its evidence, and the fact that the
   reference painter lacks it (verified by `grep`, not asserted);
2. the **measurable part** of the claim: the parity gate itself, and the fact that
   the modular engine now **beats the legacy port on all four bench images** while
   sitting **inside the CLEANROOM §3 retire gate** (≥ the reference within 2 points);
3. what remains **unmeasured** (§4) so nothing here is read as more than it is.

## 4. What is NOT claimed (read this before quoting §3)

- **No fidelity gain is claimed for the R4 constraint items** (outlines, per-style
  shaping): both *cost* MAE — `docs/checkpoints/R4-outline.md`, `R4-shaping.md` —
  and both default off. §3 is the **default** path.
- The capability matrix items are proven by their **own** instruments (unit tests,
  behavioural probes, the layer/wet benches), **not** by the parity bench, which
  has no layer stack and no wet path. "The capability is real and reachable" ≠
  "the capability improves the fidelity number".
- **H3's ≥ 70 %-usable criterion is still unmeasured** — no vision backend is
  configured here (`docs/ROADMAP_STATUS.md` H3 / Track-S S8).
- **Impasto/relief is not covered by the pinned baselines**: the visual-regression
  harness runs `--disable-gpu` and never initialises the brush engine (defect 0.7),
  so a relief-path change cannot move the 9 pins. Its evidence is the style
  modules + the app path, not the pin set.
