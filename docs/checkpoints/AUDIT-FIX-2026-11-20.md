## Fixes by audit finding

### P0-1 — Generate froze the UI 26–92 s, uncancellable
**Cause:** `engine.js#generate()` runs `buildModularPlan` synchronously on the
main thread (the modular path is the default since the R6 flip), then a
synchronous `eng.render()` of every stroke. The worker path is bypassed.
**Fix:** `audit-fix-host.wrapGenerate` runs the SAME planner in a module
Worker built from a Blob importing the real `modular-bridge.js` (identical
shapes, identical determinism), then renders in rAF-yielding chunks with a
live stroke counter. Stop terminates the worker and the render loop; the
round Generate button doubles as Stop while busy. Falls back to the original
path if Workers are blocked or the planner declines.
**Measured:** rAF heartbeat 367 beats, **max gap 0 ms** during an 18 s
generation (was: one 27,961 ms gap). Stop mid-run: status "Generation
stopped", busy cleared, `_generating=false`. 40,064 strokes, Done in 18,068 ms.

### P0-2 — Loaded image rendered black; frame collapsed to native pixel size
**Cause:** `.canvas-frame` hardcoded `aspect-ratio: 4/3` + max-width/height
caps; a 200×200 image produced a 202×151 px frame (3.9% of the window); the
canvas renders only strokes, so after load it was pure black.
**Fix:** `fitFrame()` sets the frame aspect from `engine.width/height` and
sizes it to ≈40% of the window area (LAYERS parity: 41.8%), capped 85%/72%.
A dimmed source preview (`#audit-source-preview`, opacity 0.55) shows until
the first stroke lands. A MutationObserver on `#canvas-dims` covers the
drag-drop and project-import load paths too.
**Measured:** 640×668 portrait → frame 548×572, aspect 640/668, **39.9% of
window**, preview visible; after generate preview opacity 0.

### P1-3 — Mobile Play button opened the Layers panel
**Cause:** `#toggle-controls`/`#toggle-layers` (z100, y760–804) painted over
the motion pill (z5, y766–820); `elementFromPoint` at Play returned
`toggle-layers`.
**Fix:** §20.7 lifts the pill above the toggle band
(`bottom: status-h + 44 + 12`), keeps toggles below it geometrically, pill
z-index 5 (first attempt z101 stole the React surface's Export button —
caught by the style-library flow, corrected). Chrome rows de-overlapped
(nav top 68px, header-h 168px).
**Measured:** all 4 playback buttons hit-test to themselves before AND after
generation; Play actually plays (counter advances, Layers panel stays closed).

### P1-4 — No undo; Reset/Clear/delete-layer unguarded
**Fix:** snapshot undo stack (20 deep) on generate/reset/clear/layer-add/
layer-delete; **Cmd/Ctrl+Z undo, Shift+Cmd/Ctrl+Z / Ctrl+Y redo**; Reset and
Clear Layer are two-step ("Sure? Reset", 3.5 s arm window); an undo toast
with an Undo button. Restore renders in yielded chunks (a synchronous
restore of 40k strokes would re-create the freeze).
**Measured:** undo → 0 strokes + preview back; redo → 40,064; Reset arms
(strokes intact), second click resets, toast Undo restores 40,064.

### P1-5 — Nav pill occluded the canvas header; Generate below the fold
**Fix:** §20.1 moves `.canvas-head` below the chrome band (top 56px desktop,
112/160px mobile). The Generate/Stop/Reset row is moved OUT of
`.controls-scroll` into the panel's flex column, pinned at the bottom
(`.audit-pinned-actions`) — always on screen, cannot overlap content at any
scroll offset (a sticky-inside version occluded STRUCTURE in Maestro's
viewport; caught and replaced).
**Measured:** head text + mode chip hit-test to `canvas-area` (not the nav);
Generate button on screen at y726 on a 900px viewport.

  (`paintBrush` surface) are not in the snapshot; Clear Layer is guarded but

  coverage compensation, not a UI bug; the audit's "500 → 4,064" observation
