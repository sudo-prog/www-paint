# Checkpoint H2 — Search proposer

**Date:** 2026-11-12 · Agent: BE (ThinkPad) · **Status: done** · Harness H2 (`docs/AI_STYLE_HARNESS.md`)

---

## 1. Goal

Harness **H2**: *"random / CMA-ES tunes a profile toward a target style (no LLM).
**Beats the hand-set default.**"*

The no-LLM half of the AI loop: given a base profile and a target image, search
the bounded knob space for a profile that scores better — using only the
deterministic primitives H1 landed (`KNOB_SET` / `clampKnobs` / `scoreProfile`).

## 2. Design — `js/engine/propose.js` (new, pure, deterministic)

| Export | Role |
|---|---|
| `SEARCH_DEFAULTS` | method, evaluation budget, seed, objective, `fixed`, CMA (μ,λ)/σ knobs. |
| `searchableKnobs(fixed)` | the dims a search may move: **numeric/integer/boolean knobs whose `target` is an `optimiser.*` surface**, minus those held fixed. String knobs (registry style names) and engine-only knobs the modular optimiser ignores (`multiLayer`) are excluded — the search never wanders over dimensions that cannot change the measured score. |
| `profileKnobValues(profile)` | knob values implied by the base profile's `global` block. |
| `knobsToProfile(base, knobs)` | apply `global.*` knobs without mutating the base. |
| `knobsToOptimiser(knobs)` | the `optimiser.*` overrides (count rides on the profile, not here). |
| `searchProfile(base, image, opts)` | the search → `{knobs, profile, score, baseline, improved, evaluations, history}`. |

Two methods:

- **`random`** — uniform sampling of the searchable knobs, best-of-N.
- **`cma`** (default) — a compact **(μ, λ) evolution strategy**: sample a Gaussian
  cloud around a running mean (Box–Muller from the seeded RNG), keep the elite μ,
  recompute the mean and shrink σ toward a floor. Diagonal covariance only; full
  CMA-ES covariance is deliberately out of scope.

**Two design decisions that make "beats the default" honest:**

1. **`strokeCount` is held fixed by default.** More strokes trivially raise
   fidelity, so a search that may raise them would "win" by spending more, not by
   tuning better. The comparison is therefore at **equal stroke count**.
2. **The search starts from the base profile's own values, not the schema
   defaults** — so a fixed knob (e.g. the profile's `strokeCount: 120`) is held at
   *the profile's* value, not `KNOB_SET`'s default of 400.

Guardrails preserved: **determinism** (seeded RNG, fixed `(seed)` → identical
result), **bounded action space** (`clampKnobs` on every candidate), **budget**
(hard cap on `scoreProfile` calls), **every attempt recorded** (`history` holds
wins *and* losses, tagged by generation).

## 3. Evidence

`node tests/engine.test.js` → **99/99** (6 new H2 tests: searchable-set
filtering, `profileKnobValues` + no-mutation, optimiser-override extraction,
**beats the default at equal stroke count**, determinism, fixed-knob + budget).

Measured (64² disc-on-field target, `strokeCount` fixed at **120**, budget 32
evaluations, seed 7):

| method | baseline simMae | best simMae | improved | evals | time |
|---|---|---|---|---|---|
| **cma** | 98.60 | **99.15** | yes | 32 | 1.9 s |
| random | 98.60 | 98.60 | no | 32 | 3.0 s |

CMA beats the hand-set default by **+0.55 simMae at equal stroke count** with a
32-evaluation budget; the same run is bit-for-bit reproducible. Plain random
sampling found no improvement in 32 evals — recorded honestly rather than hidden:
in an 8-dim space a small random budget is simply weaker than the ES, which is
exactly why CMA is the default.

`node scripts/visual-regression.cjs` → **9/9** unmoved (new module is not on the
app load path).

## 5. Honest assessment / next

- The search optimises the **engine's own objective** (`simMae` by default;
  `ssim` selectable). It measures through the modular engine of record — the same
  engine the parity bench uses — so a winner is a genuine Track-R fidelity gain.
- The current **objective is per-image fidelity to a target**, which is exactly
  the primitive H3/H4 need; "replicate a *style*" additionally needs the
  reference-image prompt (H3) and retrieval (H4) on top.
- The result is a **knob vector**, not yet a full profile with provenance — H3
  stamps provenance; a library UI (4.2) saves it.
- Natural follower: **H3** — a vision LLM proposes a profile from 1–4 reference
  images, then iterates with this search + the metrics as critique.
