## 1. Goal

`js/engine/order.js` (NEW) — paint-order modes over a shape list, so the
optimiser can lay strokes in an explicit sequence.

**Frozen interface (IF-4), as issued:**

```js
export function orderShapes(shapes, mode, opts = {}) -> Array<shape> // NEW array, same shapes
```

Modes: `free` `down` `up` `left` `right` `diag` `spiral` `spiralin` `rings`
`ringsin` `clock`.

---

## 2. Design

Each mode is a **stable numeric sort key** over the shape's centre
(`params[0], params[1]`):

| Mode | Key |
|---|---|
| `free` | none — input order untouched |
| `down` / `up` | `y` / `-y` |
| `left` / `right` | `x` / `-x` |
| `diag` | `(x + y) / 2` — NW → SE |
| `spiral` / `rings` | radius from centre (outward) |
| `spiralin` / `ringsin` | negated radius (inward) |
| `clock` | clockwise angle from 12 o'clock |

The **ordering centre** is resolved in this order: explicit `opts.cx/cy` → an
`analysis`-like `opts.width/height` → the **shapes' own bounding-box centre**.
The last fallback matters: without it the radial modes sort about (0,0), which
is meaningless for a shape list in image coordinates.

`free` and any unknown mode leave the order untouched. The returned array is a
**new array of the same objects** — the caller's array is never mutated — and
each shape gets `order` set to its index.

## 4. Defect the tests caught

**`clock` ran counter-clockwise.** `atan2(dx, -dy)` returns the angle measured
counter-clockwise from north (NE → +0.785, NW → −0.785 → normalised 5.498), so
an ascending sort put NW *last*. Fixed by negating the x term:
`atan2(-(x - cx), -(y - cy))` → north 0, east +0.785, south π, west 3π/2.

A second, related finding: the radial modes silently sorted about (0,0) until
the bounding-box centre fallback was added.

## 7. Hand-off notes for BE

- **Not wired** into `optimizer.js` / `generator.js` (BE-owned). `generator.js`
  already has an `orderShapes(shapes, settings, analysis)` with modes
  `free|top-bottom|spiral|one-line|edges-first` — the new module is the
  **R4-ordered** set (`down|up|left|right|diag|spiral|spiralin|rings|ringsin|clock`).
  The two should be reconciled deliberately: either map the R4 names onto the
  existing `pathOrder` setting, or replace it. **Do not leave both live with
  overlapping names** (`spiral` exists in both with different semantics).
- The new module's `spiral`/`rings` are radius-ordered; the existing
  `generator.js` `spiral` is `angle + radius*0.1`. Worth a conscious decision.
