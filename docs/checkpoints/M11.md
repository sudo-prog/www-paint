## 2. Design

| File | Role |
|---|---|
| `js/ui/export-panel-core.js` | **Pure core.** Size presets, dimension math, feasibility bounds, quality clamping, share text, filenames, error capture. No DOM, node-testable. |
| `js/ui/export-panel.js` | **DOM panel.** Renders the modal, forwards intent, shows the result. No engine imports. |
| `js/ui/export-host.js` | **Shim.** Attaches the panel to `window.__app`, supplies `getImageSize()` / `exportImage()` / `getProfileText()`. `app.js` is never edited. |

**Why a pure core:** the exit criteria are behavioural (real blobs, byte-identical
determinism, a 32px target floor). A DOM-coupled module can only prove those in a
browser; the core proves the decision logic in `node` in 200 ms, and the browser
probe then proves only what a node test cannot — that the panel actually drives
the engine.

### The ownership collision, resolved

`js/ui/export.js` + `ExportManager` + `#export-root` **already exist** and are
ThinkPad-authored; `app.js` already wires them (app.js:279–300, 777–900). The
task names `js/ui/export-panel.js`, so this stream is an **additive overlay**,
not a replacement:

- `#export-root` is never touched. `js/ui/export.js` is never touched.
- The new panel mounts on `#export-panel-root`, a sibling modal.
- The old ExportManager keeps its own `#btn-export` round button; the new panel
  has its own `#btn-export-panel` nav button.

Nothing was deleted and no existing file was modified.

### Modal, not a rail panel

The other Mac surfaces (media, library) swap the left rail. Export is a
**modal overlay** — it is not a mode, and two modals open at once is a defect.
The panel carries `role="dialog"` / `aria-modal` / Escape-to-close / a
`aria-live` status region.

### 3.6 Maestro pitfalls found the hard way (worth remembering)

1. **`assertNotVisible` cannot see a closed web modal.** The panel is closed with
   `opacity: 0` + `pointer-events: none`, NOT `display: none`, so Maestro's
   accessibility-tree check still reports the controls as visible. Assert the
   open class instead:
   `- assertTrue: "globalThis.document.getElementById('export-panel-root').classList.contains('export-panel--open') === false"`
2. **`evalScript` does not expose `document`.** `TypeError: Cannot read property
   'getElementById' of undefined`. Use `globalThis.document`.
3. **`assertTrue` needs a quoted string, not a `${...}` expression.** The
   `${...}` form is interpolated BEFORE parsing and the whole thing is then
   re-parsed as a script, which fails silently. Quoted string works.
4. **Maestro progress goes to a TTY.** Capturing stdout with `$(...)` yields
   zero `COMPLETED` lines — redirect to a file first, then grep the file.
5. **`maestro test` must be run ONE command per invocation** — the web device
   does not persist across invocations.

## 4. Defects caught

1. **`MAX_EXPORT_PIXELS` was self-contradictory.** It was set to
   `16384 × 16384` (268 Mpx) while `MAX_EXPORT_DIMENSION` was 16384, so the
   pixel check could never fire. The test caught it immediately. Now 64 Mpx
   (8192²) — below Chromium's ~268 Mpx area limit, so the panel reports a
   readable reason instead of letting the tab die.

2. **`document.createElement` interception was too broad.** The first probe
   version patched every `<a>` click, which also swallowed the anchor the
   clipboard fallback uses. Scoped to recording only.

3. **`page.evaluate` cannot see the Node `page` object.** The first probe
   version tried `page.setViewportSize` inside the page function →
   `ReferenceError: page is not defined`. Geometry is now measured from Node
   after the page function returns.

  backend returned HTTP 429 on every attempt (same as M10). The geometry
  numbers above are real DOM measurements, not a visual pass. Run vision before
  calling M11 visually done.
  - UPDATE 2026-11-13: Maestro now covers the a11y/hierarchy half (§3.5 — two new
    flows, 35/35 + 18/18, plus all four regression flows green). Vision review
    is STILL not done; the backend is now rate-limited for ~100 minutes
    (`retry_after: 6104`). Maestro asserts the accessibility tree, NOT pixels —
    so this is an a11y + hierarchy pass, not a pixel pass.
- The panel does not re-render a preview thumbnail of the export; it shows the
  summary line only. A thumbnail would need a second canvas render per change,
  which is a performance decision rather than a correctness one.
- `exportProject` / `importProject` from `exporter.js` are reachable through
  the older `#export-root` ExportManager, not duplicated here. The new panel
  surfaces only the M10 profile JSON, as issued.
