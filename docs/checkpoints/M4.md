### 1.3 Layer panel wiring (`da7d355`)

The ThinkPad landed the two `app.js` changes Mac escalated. Verified in a real
headless browser against the clean checkout:

| Claim | My result | Verdict |
|---|---|---|
| "panel renders 2 rows at init" | `{"rows":2,"styleOpts":51,"blendOpts":8,"managerLayers":2,"engineLayers":2}` | ✅ agree |
| "51 style options" | `styleOpts=51` | ✅ agree |
| style handler fires and records | `{"fired":{"layerId":1,"style":"ink"},"layerStyle":"ink"}` | ✅ agree |
| regenerate handler re-generates | `{"fired":{"layerId":1},"strokes":20}` after a real source image was loaded | ✅ agree |

⚠ **A false alarm worth recording.** My first probe reported regenerate as
broken (`strokes: 0`). It was not: the handler early-returns when
`!this.engine._analysis`, and my probe had not loaded a source image. After
loading one, the direct call *and* the UI button both produced 20 strokes. A
second apparent failure was a probe race — I read `layer.strokes.length`
before the async handler finished. **Both were probe bugs, not product bugs.**
The lesson: for async UI handlers, load the precondition *and* wait for the
effect, or you will report a defect that does not exist.

### 1.4 Page errors

1. `Error: <polyline> attribute points: Expected number, "17 4l4 4l0 0l0 0l0 0"`

   browser's default `/favicon.ico` request; the repo ships no favicon.

**Verdict: DISAGREE on the literal wording, but not a regression.** Neither
error comes from the ThinkPad's commits, both predate them, and the first is a
real (if cosmetic) defect Mac already reported in AGENTS.md §0.4. The claim
should read "0 *new* page errors".
