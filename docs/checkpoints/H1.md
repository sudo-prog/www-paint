# Checkpoint H1 — Parameter surface + headless scoring

**Date:** 2026-11-12 · Agent: BE (ThinkPad) · **Status: done** · Harness H1 (`docs/AI_STYLE_HARNESS.md`)

---

## 1. Goal

Harness **H1**: *"Style Profile params exposed as a JSON knob-set + a headless
`score(profile, image) -> metrics` primitive an AI can call."*

This is the primitive the whole AI loop stands on: before it can propose, an AI
must be able to (a) read the bounded action space and (b) measure a proposal
without a browser.

## 2. Design

### 2.1 `js/engine/metrics.js` — independent measurement (new, pure)

Canvas-free, deterministic, node-testable:

- `rasterizeShapes(shapes, w, h, background)` — composite the engine's shape list
  onto a flat fill **independently** of the app renderer, using the same
  anti-aliased ellipse-coverage model the optimiser's own paint buffer uses
  (ellipses are the modular engine's stroke vocabulary).
- `meanAbsError(a, b)` / `simMae(mae)` — the objective, and its `100·(1−MAE/255)` map.
- `ssimLuma(a, b, w, h)` — an **independent** 8×8 block-SSIM on luminance (a
  deliberately different measurement from MAE, so a proposal cannot game one number).
- `metricsVsTarget(rendered, targetPixels, w, h)` — convenience wrapper.

### 2.2 `js/engine/score.js` — the action space + the primitive (new, pure)

- **`KNOB_SET`** — a JSON-serialisable descriptor per tunable (`name`, `type`,
  `min`/`max` or `values`, `step`, `default`, `group`, and the engine surface it
  `target`s). 11 knobs today: `strokeCount, detailLevel, opacity, smart,
  coverage, elongation, scales, regionShare, style, pathOrder, multiLayer`.
  Defaults are read from `OPTIMISER_DEFAULTS` where they exist, so the action
  space cannot silently drift from the engine.
- **`clampKnobs(vals)`** — bounds a proposal against `KNOB_SET` (numbers clamped,
  integers rounded, booleans/strings coerced, unknown keys dropped). This is the
  harness's **guardrail #2 (bounded action space)** made executable.
- **`getKnobDefaults()`** — the default vector.
- **`profileToOptimiserOptions(profile, overrides)`** — maps the profile fields
  the modular engine honours (`strokeCount→count`, `detailLevel→detail`,
  `opacity→alpha`, `smart→structureAlign`) onto `optimise()` options; explicit
  overrides win.
- **`scoreProfile(profile, image, opts)`** — analyse → `optimise()` → rasterise →
  `{mae, simMae, ssim, strokes, options, stats}`. No browser, no canvas.

## 3. Evidence

`node tests/engine.test.js` → **93/93** (10 new: metrics exactness / `simMae`
endpoints / SSIM identity / rasteriser; knob-set well-formedness, defaults,
clamping, profile→optimiser mapping; `scoreProfile` range + monotonicity +
determinism).

Measured behaviour (unit test): on a 96² disc-on-field target,
`scoreProfile` at 80 strokes → **98.30 simMae / 0.9426 SSIM**, at 300 strokes →
**98.76 / 0.9600** — more strokes fit strictly better, and the run is bit-for-bit
deterministic for a fixed `(profile, seed)` (harness guardrail #1).

`node scripts/visual-regression.cjs` → **9/9** unmoved (the new modules are not
on the app load path).

## 5. Honest assessment / next

- `scoreProfile` measures through the **modular engine of record** (Track R), not
  the app's Painter — the same engine the parity bench uses. That is the correct
  target for Track R tuning; the app painter is wired at R6.
- The knob-set exposes only knobs the engine **actually honours** today; profile
  fields with no engine effect (e.g. a user `palette`) are deliberately absent
  rather than advertised.
- Natural follower: **H2** — a search proposer (random / CMA-ES) that tunes a
  profile toward a target style using `clampKnobs` + `scoreProfile`, and must
  beat the hand-set default. The pieces it needs now exist.
