## 2. The mechanism, in one paragraph

A mix retunes the **pass schedule** rather than inventing a renderer. Weights are
normalised to sum 1; the numeric stroke-language fields (`radiusMul`, `blur`,
`elongMul`, `alpha`, `detail`) are the weighted average of the mix, while enums
(the registry style, the brush tip) come from the **dominant** primitive. A
single primitive returns its numbers verbatim. An explicit per-pass
`radius`/`blur`/`elongation`/`alpha`/`detail` still wins over the mix — the mix
fills the gaps. An empty/absent/unknown mix changes **nothing at all**.

## 3. Verified, not asserted

`node scripts/primitives-probe.cjs` → **PASS** (exit 0), with these measured
results:

- **Resolution** — all 6 primitives resolve to an existing style
  (`getStyle` non-null) and an existing `MEDIA_PRESETS` entry. Probe fails if a
  name is renamed away.
- **Algebra** — unknown ids and zero weights dropped; canonical order
  (`wet-wash` before `hatch`); sums to 1; normalisation is a fixed point; an
  unknown id is a validation **error**, not a silent drop.
- **No-op until opted in** — shapes identical and the geometric plan
  byte-identical for `primitives: null`, `{}`, and an all-unknown mix; no key is
  added to the plan.
- **The mix moves the paint** — plan changed, output changed, deterministic for a
  fixed seed, same stroke count, explicit per-pass override wins.
- **The AI half** — 40 evaluations from a uniform 0.3 mix: **96.3843 → 97.0925**,
  returning a **non-empty** mix, deterministically. (A search that prefers the
  empty mix is reported as such, not dressed up.)

## 4. The honest scope — what S5 does NOT claim

- **No fidelity claim.** The primitive geometry/media numbers are a *declared*
  language, hand-set from each medium's character. They are not a measurement.
  The probe's per-primitive table is **photo-fidelity** on synthetic content, and
  it is expected to get *worse* for `wet-wash` and *better* for `hatch` — that is
  the feather-versus-detail trade S2 documented, not a defect.
- **No "matches a reference" claim.** Whether a mix scores well against a
  reference is **S10**'s (content × ref-set) matrix, which does not exist yet.
- **No app-UI claim.** The mixer UI is **M16** (Mac). BE wired the app's style
  resolution; BE did **not** browser-verify the new primitive render path — the
  browser gates below prove the *pre-S5* path is unchanged, which is the
  regression claim, and that is all they claim.
- **Layer mixes are carried, not applied by the optimiser.** The modular engine of
  record emits one shape list, so it has one language per pass; a per-layer mix is
  for the multi-layer renderer / the UI. A layer mix is deliberately **not**
  promoted to the profile-level mix (pinned by a test).

## 6. Browser regression (the pre-S5 path)

`scripts/visual-regression.cjs` renders through the real `PaintingEngine`
(`js/engine/engine.js`), so the 9/9 unmoved pins cover S5's engine change with the
pinned styles: a profile-less paint is unaffected. `scripts/profile-probe.cjs`
(the Phase-4.1 profile path in the browser) is run as the companion check that a
profile **without** primitives still drives settings, seed, band styles and
`opts.style` exactly as before. Its result is recorded in the OPS_LOG line for
this landing.
