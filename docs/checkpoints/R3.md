# Checkpoint R3 — CCL + PCA stroke initialisation

**Date:** 2026-11-11 · Agent: BE (ThinkPad) · Track R (`docs/CLEANROOM.md`) · **Status: done**

---

## 1. Goal

Milestone **R3** (`CLEANROOM.md` §4, roadmap **1.4**): *better stroke initialisation —
CCL + PCA orientation/size — plus dual-stage residual refine. Fidelity ≥ reference at
equal stroke count; beats the previous (R2) baseline.*

R2 sharpened contours but every dab was still an axis-aligned, structure-tensor-oriented
ellipse proposed from the residual map. R3 adds a **structural initialisation**: segment
the target into connected components, fit each component's principal axis, and seed
strokes from the region's own geometry — so an elongated feature starts as one oriented,
region-sized mark instead of several generic dabs.

## 2. Research (cited techniques)

- **Connected-component labelling + principal-component analysis** stroke initialisation —
  the classical step that quantises an image, labels its connected regions and fits each
  region's principal axis to derive stroke orientation and size. Cited as a technique in
  `docs/REFERENCES.md` / `ROADMAP.md` §3; re-derived here from the published method, with
  no identifier, table or control flow taken from any implementation.
- Structure-tensor SBR (roadmap 1.2) — the existing R2 elongation path, unchanged and
  still the residual passes' orientation source.

## 3. Design

### 3.1 `js/engine/regions.js` (new, pure, node-testable)

A dependency-free, deterministic, canvas-free module:

1. `quantizeBins(pixels, w, h, levels)` — quantise RGB into `levels³` uniform colour bins
   (default 6³ = 216) so near-identical colours group into flat fields.
2. `labelComponents(bins, w, h, connectivity)` — two-pass connected-component labelling
   with union-find; pass 2 renumbers and accumulates per-component moments (area, Σx/Σy,
   Σx², Σxy, Σy², bbox) in the same scan.
3. `pcaFromStats(stats)` — eigen-decomposition of the coordinate covariance →
   centroid, major-axis `angle`, eigenvalues `l1 ≥ l2`, `elong = √(l1/l2)`.
4. `buildRegions(analysis, options)` — quantise → label → colour means → PCA → filter
   (drop `< minArea` and `> maxAreaFrac·W·H`), largest-first.
5. `fitEllipse(region)` — converts the eigenvalue spread to major/minor half-extents
   (`extent = √(12·λ)` for a uniform bar).

Regions carry `area, cx, cy, l1, l2, angle, elong, fill, color, bbox`.

### 3.2 Optimiser integration — `regionInitPass` (`js/engine/optimizer.js`)

A new pass runs **before** the coarse→fine schedule:

- Only **clearly elongated** components (`elong ≥ regionMinElong`, default **2.5**) are
  seeded — the case where one oriented stroke does the work of several residual dabs.
- Each is covered by a short chain of ellipse dabs laid **along its principal axis**,
  sized to the region's cross-section (`regionMaxSegments`, default 3), inflated by
  `regionMargin` (default 1.3) to close the seams between segments.
- Every dab takes the component's **mean** colour, so a flat region is initialised with a
  near-exact mark.
- Compact/isotropic and ring-like components are **skipped** — the residual schedule fits
  them better (see §6) and skipping keeps the pass from blanketing the canvas (R0's
  failure mode).
- Budget: `regionShare` (default **0.08**) of `count`; the schedule then spends
  `count − regions` with its pass weights applied to *its own* total, so the stroke count
  stays **exact**. Opt out with `regionInit: false` (byte-identical R2 output).

No randomness is used anywhere in the pass, so it is deterministic.

### 3.3 Dual-stage residual refine

The region seed is the *first* stage; the existing R2 per-stroke hill-climb + coarse→fine
residual passes are the *second* — they now work against a canvas that already carries the
structural lay-in, so their budget is spent on what the init did not cover.

## 4. Evidence — parity bench (seed 12345, 400 shapes, 256², independent MAE + SSIM)

| image | R2 simMae / SSIM | **R3 simMae / SSIM** | Δ simMae | Δ SSIM | reference simMae | R3 gap |
|---|---|---|---|---|---|---|
| blobs  | 97.52 / 0.8671 | **98.08 / 0.8902** | **+0.56** | **+0.0231** | 99.54 | 1.46 |
| rings  | 98.01 / 0.8522 | 98.01 / 0.8522 | 0.00 | 0.0000 | 99.52 | 1.51 |
| smooth | 98.78 / 0.9317 | **98.88 / 0.9336** | **+0.10** | **+0.0019** | 99.67 | 0.79 |
| noise  | 80.89 / 0.0256 | 80.88 / 0.0257 | −0.01 | +0.0001 | 81.17 | 0.29 |

R3 improves **both** metrics on the two images that carry elongated structure: `blobs`
(the image with the largest R2 gap, which includes a rectangle and a triangle) gains
**+0.56 simMae and +0.023 SSIM**, closing its gap to the reference from 2.02 → **1.46**;
`smooth` gains +0.10 / +0.0019. `rings` (concentric annuli — rotationally symmetric, so
PCA is isotropic and nothing is seeded) is unchanged. `noise` — the deliberate unfittable
negative control — moves −0.01 simMae, i.e. within measurement noise.

**Defaults were tuned by measurement, not by eye:** a Playwright sweep drove the *real*
parity-harness images and their independent MAE+SSIM across ~40 option variants
(`regionShare`, `regionMinElong`, `regionMargin`, `regionMaxSegments`, `regionLevels`,
`regionMaxAreaFrac`, `regionMinArea`). The chosen set improved both metrics on *both*
structured images; every candidate that spent more budget, seeded less-elongated regions,
or patch-filled compact ones scored worse.

Tests: `node tests/engine.test.js` → **73/73** (10 new: 5 `regions.js` unit tests + 5 R3
optimiser tests — budget exactness, PCA orientation, determinism, opt-out, defaults
consistency). `node scripts/visual-regression.cjs` → **9/9**, baselines unchanged —
`optimizer.js`/`regions.js` are not on the live app load path.

## 6. Honest assessment / next

The gain is **real but modest and structure-dependent**, and honestly bounded:

- The R2 residual optimiser is already strong, so a region-init pass that *consumes*
  budget only pays off where the seed genuinely beats several dabs. Measurement showed
  the failure modes directly: seeding less-elongated regions, spending a larger share
  (0.15–0.30), or **patch-filling compact regions** all *reduced* fidelity — the
  patch-fill path was written, measured, and **removed** rather than shipped.
- On a **bare synthetic bar** on a flat field the residual schedule alone was already at
  parity and the init was neutral-to-slightly-negative (dab spill), so no unit test
  asserts "region init improves fidelity" on a synthetic proxy — that claim is backed
  only by the real bench. This is the R2 lesson ("don't tune or verify with a synthetic
  proxy") applied again.
- The next fidelity lever is the one R2 identified and R3 does not address: dabs are
  still **smooth ellipses**. `rings` is unmoved because an annulus has no principal axis.
  Giving the painter a *stroke*-shaped / curved primitive (**R4**: outlines, region-fill,
  path modes, per-style shaping) is what will move curved structure.
