## 1. What S10 is for

S1–S9 each added a piece of style measurement. **S10 is the gate**: a FIXED matrix
whose numbers are PINNED, so a change that moves Style-Match cannot land unnoticed.
It is the sibling of the visual-regression harness — that one pins *pixels*, this
one pins *style*.

## 2. The construction (and why it is what it is)

A reference packet analysed from a render on **different** content is dominated by
the content mismatch: comparing across contents measures *"is this the same
picture"*, not *"is this the same stroke language"*. The first draft of this bench
did exactly that and produced a meaningless matrix (every cell ~0.4–0.9, driven by
content). So the references are rendered **on the same content as the candidate**:

| Axis | Value |
|---|---|
| **content-set** | 3 deterministic procedural images: `blobs`, `rings`, `stripes` (256²) |
| **ref-set** | 9 pinned registry styles, rendered **per content** through the real `PaintingEngine` (seed `3047602159`, **700** strokes), analysed with the S1 analyser (`analyzeReference`) |
| **candidate** | a fixed-cost profile for style `t` (`{ global: { style: t, strokeCount: 200, detailLevel: 0.7 } }`) rendered on the same content |
| **cell `(c,t,s)`** | `scoreProfileStyle(candidate_t_on_c, c, refsPerContent[c][s])` → `styleMatch` |

Within a content block the content is held **constant**, so a cell varies the
stroke language and nothing else. 3 × 9 × 9 = **243 cells**.

## 3. The headline — and it is not a comfortable one

**A style's own reference is the best match in only 3 of 27 (content, style) rows.**

```
blobs/pencil      own 0.4082  bestOther 0.5129 (halftone)   margin -0.1047  LOSS
blobs/charcoal    own 0.8900  bestOther 0.8501 (watercolor) margin +0.0399  WIN
rings/marker      own 0.6506  bestOther 0.6076 (pencil)     margin +0.0431  WIN
rings/graphic     own 0.4326  bestOther 0.7319 (marker)     margin -0.2992  LOSS
stripes/charcoal  own 0.9098  bestOther 0.7023 (watercolor) margin +0.2075  WIN
... 3/27 rows are WINs
```

styleMatch range across the whole matrix: **0.143825 … 0.954154**.

This is the S2 §6 caveat, quantified on content held constant: the composite does
not currently identify a style. It separates *grossly* different stroke languages
(H-S5's cross-hatch margin +0.0943 survives) but not near-neighbours, and — as the
`blobs` row shows — it can prefer a broadly-similar style over the right one.

**Why this is a legitimate result and not a broken bench.** `ownIsBest` is
REPORTED and pinned, never asserted as a threshold. Asserting "the diagonal must
win" would be asserting a claim the metric has not earned; hiding the 3/27 would be
worse. The suite pins today's behaviour so any change is *visible*, and hands S9 a
precise, reproducible target.

### 3.1 The confound, stated plainly

The candidate is rendered at **200** strokes while every reference is **700**, so
the diagonal is *not* a like-for-like render: a sparse render is compared against a
dense one. That difference is a plausible driver of the low diagonal, and it is the
first thing S9 should remove (equal-cost references, or a cost-normalised metric)
before re-pinning. Equalising at 700 would make the matrix ~4× slower; equalising
at 200 makes the diagonal compare a render against itself (trivially ~1). Neither
is obviously right — which is exactly why S9 owns it, not S10.

## 4. The gate

- Pinned: `docs/research/style-accuracy/baseline.json`, tolerance **1e-9**, keyed by `content|candidate|reference`.
- Default run **writes nothing** — a gate must not dirty the tree.
- `--update` re-pins deliberately; `--json=<path>` dumps a run record; `--tol=` overrides.
- `--replay=<record.json>` re-runs **only** the gate over a recorded matrix — no
  browser, no `NODE_PATH`, milliseconds. That is what makes the guard verifiable
  both ways on any machine.

**Verified BOTH ways** (same binary):

|---|---|
