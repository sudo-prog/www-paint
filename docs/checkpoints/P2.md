## 1. Goal A — tonal masks

### 1.1 Research

Tonal separation is the standard painterly approach to value structure: a
painting is laid in large flat value shapes first, then the value ranges are
refined. The machine-readable version of that is four overlapping bands —
background / shadows / midtones / highlights — that a layer-aware generator can
weight per region (Phase 2.2, ThinkPad's consumer).

The design constraint from IF-1: **additive only, node-testable on a plain
buffer, no DOM**, consuming an existing `analyzeImage()` result whose
`luminance` is a `Uint8ClampedArray`.

### 1.2 Design

Each band is a **smooth window** over luminance, not a hard threshold, so no
visible seam lands where a band edge falls:

| Band | Definition |
|---|---|
| `background` | `1 − smoothstep(L, 0, 255·t)` — the paper / darkest flat region |
| `shadows` | `(1 − smoothstep(L, lo−s, lo+s)) · (1 − background)` |
| `midtones` | `smoothstep(L, lo−s, lo+s) · (1 − smoothstep(L, hi−s, hi+s))` |
| `highlights` | `smoothstep(L, hi−s, hi+s)` |

`smoothstep` has zero derivative at both ends, so the windows join smoothly.
The four windows form a **partition of unity** — they sum to exactly 1.0 at
every pixel — which is what makes the coverage fractions sum to ~1 and lets a
downstream consumer blend the four contributions with no gaps or double-weight.

`background` is deliberately a *real* band rather than a residual: a residual
after the three tonal windows is identically zero, because those windows
already tile the whole range. Giving it its own window (fading out by
`255 · backgroundThreshold`, default 0.15) means it claims the genuinely-dark
paper without eating real shadow detail.

### 1.4 Bug found in the analyzer (ThinkPad-owned — reported, not fixed)

`analyzeImage()` **hangs forever on images smaller than `paletteSize`
pixels**. The k-means init loop in `extractPalette`:

```js
for (let c = 0; c < clusters; c++) {
  let idx;
  do { idx = Math.floor(rnd() * (data.length / 3)) * 3; }
  while (used.has(idx));      // ← spins forever when data.length/3 < clusters
  used.add(idx);
  ...
}
```

With fewer than 16 pixels there are fewer than 16 distinct indices, so the
`do/while` can never satisfy `used`. Reproduced with a 1×1 buffer (hangs
indefinitely). `js/engine/analyzer.js` is ThinkPad-owned, so it was **not**
edited — raised via OPS_LOG. The mask tests work around it by feeding a
hand-built analysis object for the degenerate case and documenting the minimum
viable size.

### 2.4 ⚠ ESCALATION — app.js changes needed (ThinkPad-owned)

Per `HANDOFF.md` §5 M2 ("If wiring needs an edit to `js/ui/app.js` or
`js/ui/controls.js`, **stop and raise it via OPS_LOG**"), two changes are
needed in `js/ui/app.js`. Both are small; neither was made here.

**(a) Sync the panel at init** — after line 103 (`this.layers = new LayersManager(...)`):

```js
this.layers.setStyleOptions(
  this.engine._styleList.map(n => ({ value: n, label: n }))
);
this.layers.setLayers(this.engine.layers);
```

Without this the panel opens empty. (`engine._styleList` is populated by
`_registerAllStyles()`, called at app.js:96.)

**(b) Handle the two new events** — alongside the existing layer handlers:

```js
this.layers.root.addEventListener("layer-style-change", (e) => {
  const layer = this.engine.getLayer(e.detail.layerId);
  if (!layer) return;
  layer.style = e.detail.style;
  // Re-render only if the layer already has strokes; the style is read per
  // stroke at draw time, so a layer with no strokes needs no repaint.
  if (layer.strokes.length) this.engine.render();
});

this.layers.root.addEventListener("layer-regenerate", async (e) => {
  const layer = this.engine.getLayer(e.detail.layerId);
  if (!layer) return;
  const style = layer.style || this.engine.settings.style || "pencil";
  const seed = (this.engine._seed || 1) + layer.id;
  const shapes = await this.engine.generate({
    style, layer: layer.id, seed,
    count: this.engine.settings.strokeCount,
  });
  layer.strokes = shapes;
  this.engine.render();
  this.layers.setLayers(this.engine.layers);
});
```

`engine.generate()` is ThinkPad-owned and already supports `{style, layer, seed,
count}`; no engine change is required.

### 2.5 Known limits

- **Layer-level style is advisory until (b) lands.** The dropdown emits the
  event and the row reflects the choice, but the engine does not yet re-render
  with it.
- **Regenerate** emits `layer-regenerate`; without the app.js handler it does
  nothing.
- **No reorder (drag) wiring.** `engine.moveLayer()` exists but nothing calls
  it; the drag handle is rendered but inert. Not in this stream's exit
  criteria, and wiring it needs app.js.
