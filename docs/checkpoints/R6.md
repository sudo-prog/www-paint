## 3. NEW — the switch is proven under the app's REAL configuration

`js/ui/app.js:89` constructs the engine with **`useWorker: true`**, so a switch
proven only on a `useWorker: false` engine would not be proven for the product.
`scripts/modular-switch-probe.cjs` now drives **both** engines; re-run on this tree:

```
$ NODE_PATH=<playwright-core> node scripts/modular-switch-probe.cjs
=== modular-engine switch probe @ 1440x900 ===
  ✓ default settings.modular is false (got false)
  ✓ modular generate returns shapes (261)
  ✓ painter generate returns shapes (250)
  ✓ every modular shape is engine-format (params + color0)
  ✓ modular path paints ink (18955 px / 32 colours)
  ✓ painter path paints ink (39431 px / 582 colours)
  ✓ modular works under the APP config (useWorker:true) — 261 shapes
  ✓ every shape is engine-format under useWorker:true
  ✓ the worker-configured modular path paints ink (18955 px)
  ✓ 0 non-404 console errors (got 0)
PASS
```

The worker-configured run returns the **identical** 261 shapes / 18955 px, because
the modular branch sits **before** the worker branch in `generate()` and returns
early. That ordering is now **pinned by the probe** rather than assumed — it is the
one design call the R5/R6 bridge note left open ("mirror the branch in the worker
path, or fall back to the main thread"). The answer is: **neither** — the modular
branch takes precedence and the worker is not consulted, so there is no second code
path to keep in sync.

## 5. The one decision this milestone needs

**Should the app's DEFAULT engine become the modular engine (and the 9 pinned
baselines be re-baselined to it)?**

- **For:** the gate is met, the modular engine beats the port on the bench, and
  every R1–R5 capability (profiles, layers, wet media, AI loop) hangs off it — R6
  is the milestone that makes them reachable by users by default.
- **Against / cost:** the app's *look* changes (the modular optimiser emits
  ellipse dabs rendered through the chosen style; the Painter's own shape mix and
  motion playback are not reproduced stroke-for-stroke), the 9 pins move, and any
  hand-tuned Painter behaviour that users rely on becomes opt-out rather than
  default.
- **Middle path, and the one I would take:** keep `modular` an **opt-in toggle**
  (the Mac's UI is landing one), ship it, and flip the default only after a
  side-by-side look at the app on real images — the bench says *fidelity*, and
  fidelity is not the only thing a user sees.

Nothing in this checkpoint pre-empts that call: no default changed, no baseline
moved.
