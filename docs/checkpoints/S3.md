# Checkpoint S3 — Multi-reference fusion (Track S)

**Date:** 2026-11-13 · Agent: BE (ThinkPad) · Stream **S3** (`docs/TRACK_S.md` §3)
**Status:** mechanism complete; exit criteria met. **But this note contains a
finding that matters more than the feature — §7: two defects in S2 that make its
stated measurement impossible. Read §7 before trusting any style-match number.**

---

## 1. Goal

S1 gave a reference a machine-readable stroke language (`RefPacket`); S2 made it
comparable. S3's exit criterion: *"1–4 refs fuse into one packet deterministically;
an outlier ref is down-weighted; fused packet round-trips through the schema."*

The reason it exists: a profile built from **one** reference inherits that
reference's accidents. A user who drops 1–4 style references wants the style they
*agree* on, not whichever image happened to be listed first.

---

## 2. Design

**`ref-analyze.fuseReferences(refs, opts) → FusedPacket`** (`module: 'ref-fusion'`),
pure and deterministic — no second analyser, no randomness. A reference may be a
`RefPacket` or a `{ packet, weight }` wrapper.

**Weights.** Input weights normalise to a distribution (all-zero ⇒ equal). The
effective weight of an outlier is multiplied by `outlierWeight` (default `0.25`) —
**down-weighted, never dropped** (the census must still be visible in `refs[]`).

**Outlier rule.** Pairwise style distance (reusing S2's `refPacketDistance`, so a
reference is judged by the *same* measure a render is) → each reference's mean
deviation from the others → a reference is an outlier when
`deviation > outlierThreshold AND deviation > outlierRatio × median(deviation)`.

> The `AND`, the absolute floor and `outlierRatio = 1.5` are all load-bearing. For
> the common "two inliers + one black sheep" case the sheep's deviation is exactly
> `2 × median`, so **`outlierRatio = 2.0` silently never flags anything** — this
> was caught by the unit tests, not by reading the code. The absolute floor stops a
> tight cluster being split by noise; the `AND` means a genuinely scattered
> reference set flags nobody (and says so, via `spread`).

**Merged fields** (weighted means, per-field): `scaleHistogram` and
`orientationField.bins` as *distributions* (each renormalised first, then again),
`strokeScaleByBand`, `coverage`, `depthProxy`, `stats`, and `orientationField.dominant`
as a PI-periodic weighted circular mean over doubled angles.

**Palette.** Merged by rank-weighted accumulation (earlier palette entries are more
dominant), ties broken by hex for determinism, capped by `paletteSize` (16).

**`spread` — a confidence signal** (H-S2): mean pairwise agreement, plus the scale
/ orientation / coherence spread across refs. This is how the caller learns the
references *disagree*.

**Parser support.** `analyzeReference` now also emits a compact `styleDNA`
(`palette`, `edgeDensity`, `contrast`, `wetnessEstimate`, `tones`) — **additive**,
same single pass, still JSON-safe. `wetnessEstimate` is an explicit **PROXY**
(`1 − meanCoherence`: wet media bleeds and destroys the crisp directional
anisotropy dry work holds), documented as such in the code — not a measurement.

**Schema.** `provenance.refPacket` added as an **optional** field
(`docs/STYLE_PROFILE.md` §2 / §3.5 / §6) — `schemaVersion` stays 1 per the
versioning rules. `profile.js` gains `attachFusedReference(profile, fused)`
(returns a NEW profile; the input is never mutated) and
`fusedReferenceFromProfile(profile)`; `validateProfile` rejects a malformed
`refPacket`. Because the fused object *is* `RefPacket`-shaped, `refPacketDistance`
/ `scoreProfileStyle` consume it with **no new code path**.

Structural, on hand-built packets (fusion is arithmetic on packets, so a synthetic
fixture is the correct — and exactly reproducible — one): a 1-ref fusion reduces to
its source in four of five terms; identical inputs are byte-identical; a black
sheep among two inliers is flagged and carries exactly `0.25/2.25` of the weight
(and `1/3` when down-weighting is disabled — proving the down-weighting is what
changes it); explicit per-ref weights override the default; two refs flag nobody;
identical refs agree fully (`spread.agreement === 1`); the fused packet is
JSON-safe and its distributions each sum to 1; palette ordering is
`['#111111','#222222','#333333','#abcdef']`; 0 refs / \>4 refs / non-packets all
throw; `provenance.refPacket` round-trips JSON **and still validates**; a malformed
`refPacket` is rejected; `attachFusedReference(…, null)` clears the key. Plus one
test on **real** `analyzeReference` output (square + ring), so the feature is not
only exercised on fixtures.

## 7. ⚠ FINDINGS — two defects in S2, found while testing S3

S3's fusion reuses S2's distance, so S3's tests probe it directly. That surfaced
two problems. **Both are real, both are reproducible, and neither is fixed here** —
fixing them changes S2's measured numbers, so they need their own measured
validation, not a drive-by. Recorded because S2 §6 explicitly assigned the first
one to S3 to look at.

### Defect A — `orientationMatch` is not a metric (identity fails)

`metrics.orientationMatch(a, b)` documents *"1 = the same distribution"*. It is not:
its denominator is a **weighted mean of cos(2Δθ)**, which penalises **spread**. For a
DELTA histogram (every pre-existing test) identity gives exactly 1; for a **broad**
histogram — i.e. every real render — two *identical* inputs score **~0.5**.

Consequence, measured on the real S1 analyser (`analyzeReference` of a 128px square):

```
refPacketDistance(p, p).distance = 0.1206      (must be 0)
  parts: scale 0, orientation 0.4826, coverage 0, bandScale 0, coherence 0
⟹ styleMatch has a FLOOR of 0.8754 — a render identical to its reference
  can never score above 0.875.
```

This *is* the S2 §6 mystery ("the orientation term reads ≈0.50 against both
references — a coin flip"): it is not the data, it is the kernel's denominator.
The correct form normalises by the kernel **self-products** `sqrt(K(a,a)·K(b,b))`
(`K(i,j) = cos(2(i−j)step)` is PSD, so Cauchy–Schwarz bounds the ratio to exactly 1
at `a === b`, for any distribution; delta-vs-delta is unchanged).

> **⚠ SUPERSEDED 2026-11-14 (H-S5).** This section originally read "**It was
> implemented, measured, and reverted** — see B for why applying it now would be a
> change nobody could validate", and the `KNOWN DEFECT` tests pinned the buggy
> behaviour. **B is fixed (H-S6, 2026-11-13) and A is now fixed too** —
> `js/engine/metrics.js` implements the self-product normalisation, and the pinned
> tests are inverted. The re-measurement is in `docs/checkpoints/H-S5.md` §4: the
> corrected kernel earns its weight on a genuinely different reference pair
> (+0.0943 pencil profile vs cross-hatch), and the pencil-vs-ink pair this section
> measured as `orientationMatch 0.9636` is now reported as a KNOWN LIMITATION
> (margin −0.0304) rather than assumed to be the discriminating case.

### Defect B — `scoreProfileStyle` renders through a STYLE-AGNOSTIC path

`scoreProfileStyle` builds its render with `optimise(analysis, opts)` →
`rasterizeShapes(shapes, w, h, bg)`. The clean-room optimiser emits un-styled
shapes and the harness rasteriser draws plain ellipses — **neither reads the
profile's `style` at all.** Measured, same content, same seed, same cost:

```
pencilProfile vs pencilRef 0.887   inkProfile vs pencilRef 0.887
pencilProfile vs inkRef    0.928   inkProfile vs inkRef    0.928
grid_orientationTerm: identical for BOTH profiles (0.3972 / 0.2215)
```

The two profiles produce **byte-identical** scores. So S2's "style match" currently
measures *the optimiser's stroke geometry* against a style reference — the one
thing a style profile controls (`global.style`) is not in the loop. That is why S2
could only ever report a margin of +0.0027.

Supporting measurement: the two references are also weak on their own terms —
`orientationMatch(pencilRef, inkRef) = 0.9636` (`refPacketDistance` 0.0364), because
both are 700-stroke renders of the **same content**.

With B standing, A cannot be validated: S2's only real-world check
(`scripts/style-match-probe.cjs`) compares a style-agnostic render to two
same-content references. Applying A alone turned that probe **red** (margin
+0.0027 → −0.041) *without* making the measurement more meaningful — the
orientation term (weight 0.25) began discriminating on a signal that carries no
style. So the change was reverted and the probe is green again at its original
numbers.

**What this means:** S2 is correctly described as *"mechanism done, direction
confirmed, magnitude not meaningful"* — and now we know **why**. Making style-match
real needs (1) a render path that honours `global.style`, and (2) genuinely
different style references. Both are prerequisites for S9's refinement, not
side-effects of S3.

## 8. Hand-off notes

- **S3's rule is RELATIVE** (deviations compared to each other), so Defect A — an
  absolute floor on the distance — largely cancels inside it. That is why fusion is
  sound despite A. Nothing else in S3 depends on an absolute distance.
- Fix **B first, then A**: B is what makes the measurement mean anything; A is a
  one-function change that must be validated against B's fixed render path. Do not
  ship A alone — it will turn the probe red for no gain (measured).
- `docs/STYLE_PROFILE.md` §6 records `provenance.refPacket` as a permitted optional
  addition; the vendored-LAYERS-AJV swap (integration Phase B) must not drop it.
- `fuseReferences` throws on \>4 refs (matches the schema's `refs` `maxItems: 4`).
  If the UI ever wants more, raise `maxRefs` deliberately rather than clamping
  silently.
