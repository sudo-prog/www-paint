# Checkpoint P5.5 — Optional neural stroke-set warm-start

**Date:** 2026-11-17 · Agent: BE (ThinkPad) · Roadmap **Phase 5.5**
**Exit criterion:** *"Documented; optional path."*

---

## 1. What 5.5 asks for

Roadmap §5, Phase 5.5: *"Optional neural stroke-set warm-start — AttentionPainter /
Paint Transformer ideas; **can stay heuristic** — exit: **Documented; optional path**."*

The intent is the AI loop's "learns from what worked before" step: a *new* style
proposal should start closer when a **similar reference** has been seen before,
rather than from the schema defaults every time. The roadmap explicitly allows the
heuristic form, so 5.5 is satisfied by an **opt-in warm-start path that reuses the
existing feedback store** — no trainable model is required for this item.

## 2. What already existed

Harness **H4** (`js/engine/memory.js`, `docs/checkpoints/H4.md`) already shipped the
two halves of the mechanism:

- `averageHash(pixels, w, h)` — a 64-bit coarse perceptual signature
  (`hamming`/`maxDistance` make "similar" an explicit predicate), and
- `createMemory()` with `warmStart(queryHash, o)` → `{ init, from, distance, score }`,
  *"shaped for `propose.searchProfile(base, image, { init })`"*.

**But nothing called it.** `searchProfile` accepted an `init` vector and never
consulted the store, so the warm-start half of H4 was inert (the H4 test wired it by
hand: `init: ws ? ws.init : undefined`).

## 3. What shipped (this checkpoint)

`js/engine/propose.js` — the proposer now accepts an **optional feedback store**:

```js
searchProfile(base, image, { memory, warmStart })   // both opt-in, default off
```

- `SEARCH_DEFAULTS.memory = null`, `SEARCH_DEFAULTS.warmStart = {}`.
- When `memory` is a store (an object with `warmStart`), the search computes
  `averageHash(image.pixels, image.width, image.height)` and seeds the start vector
  from `memory.warmStart(hash, warmStart)`. An explicit `opts.init` still **wins**
  over the warm values (spread order: warm first, explicit second).
- The result gains `warmStart: { used, hash, from, distance }` — so a caller can
  tell whether a warm start applied, from which stored entry, and at what distance.
- **Absent `memory` ⇒ nothing changes**: no hash is computed and the search is
  bit-for-bit the previous one (the `init` chain is identical).

## 4. Honest scope

- This is the **heuristic** form the roadmap permits — a nearest-neighbour warm
  start over a coarse aHash signature. It is **not** a neural stroke-set predictor
  and makes **no claim of a fidelity gain**: 5.5's exit criterion is "documented;
  optional path", not a measured improvement.
- The *whatever it proposes still has to win under the H5 gate*: a warm start only
  moves the search's starting point; `searchProfile` still returns the best scoring
  vector found and never worse than its own baseline.
- A genuinely learned stroke-set prior (AttentionPainter / Paint Transformer) is
  **Phase 7 stretch**, not this item.

## 5. Evidence

```
$ node tests/engine.test.js      -> Passed: 165  Failed: 0
```

New test — *"5.5: the proposer warm-starts from the feedback store, opt-in and
unchanged by default"* — asserts all four properties:

1. no `memory` ⇒ `warmStart.used === false` **and** `warmStart.hash === null`
   (the default path computes no hash and changes nothing);
2. a store seeded with the query's own hash ⇒ `used === true`, `hash` equals
   `averageHash(...)`, `from === 0`;
3. deterministic with a store (same knobs + score on a re-run);
4. an **empty** store ⇒ `used === false` and output byte-identical to the default.

No render path was touched, so the 9 pinned visual baselines cannot move.
