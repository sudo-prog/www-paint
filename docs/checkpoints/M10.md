# Checkpoint M10 — Style Profile library UI (Phase 4.2)

**Date:** 2026-11-12 · Agent: Mac / AIR HERMES · Stream **M10** (Round 2 / `docs/MAC-TASKS.md` R2.2)
**Goal:** save / load / apply / export / import a Style Profile in one click,
deterministically re-bakeable with a seed · **Status:** delivered, browser-verified

---

## 1. Goal

`js/ui/style-library.js` (+ host shim). The engine side (4.1) was already done
by BE: `js/engine/profile.js` validates / normalises / expands a profile, and
`engine.generate({ profile })` consumes it. This stream is the **user-facing
surface** against the frozen schema (`docs/STYLE_PROFILE.md`, draft-07 v1).

**Frozen interface, as issued:**

```js
js/ui/style-library.js       // panel: save / list / apply / delete / export / import
js/ui/style-library-host.js  // the media-host.js shim pattern (never edit app.js)
```

> The **profile object is the contract, not the storage** — persistence stays
> behind a small adapter.

---

## 2. Design

Split in two, the same shape as the media panel:

| File | Role |
|---|---|
| `js/ui/style-library-core.js` | **Pure core.** The profile object, schema validation, the storage adapter, export/import, apply-expansion. No DOM, node-testable. |
| `js/ui/style-library.js` | **DOM panel.** Renders rows, forwards intent, dispatches `style-profile-apply`. No engine imports. |
| `js/ui/style-library-host.js` | **Shim.** Attaches the panel to `window.__app`, supplies `getSnapshot()`, consumes the apply event. `app.js` is never edited. |

**Why a pure core:** the exit criteria are behavioural (schema-valid, byte-identical
round-trip, deterministic re-bake). A DOM-coupled module can only prove those in
a browser; a pure core proves them in `node` in 200 ms, and the browser probe
then proves only what a node test cannot — that the panel actually drives it.

**Storage adapter:** a three-method interface (`getItem`/`setItem`/`removeItem`).
`localStorage`, `IndexedDB` or a plain `Map` all work; a missing or throwing
adapter degrades to in-memory rather than throwing. Verified by test.

## 4. Defects caught

| # | Defect | Cause | Fix |
|---|---|---|---|
| 1 | `SyntaxError: Duplicate export of 'StyleLibraryPanel'` — the whole module failed to load, so **nothing** worked | `export { X as default }` plus `export { X }` in the same module | `export default X` |
| 2 | **Save was silently dead.** The Save button did nothing and the status stayed empty | The delegated click handler was gated on `e.target.closest('[data-action]')`, but the panel-level buttons (Save / Import / Choose file) carry an **id**, not a `data-action` — so `btn` was null and the handler exited before reaching the id checks | Look up both selectors; the id-only buttons are handled explicitly |
| 3 | **A minimal but schema-valid profile could not be saved** — `save()` threw `mediaModel: must be an object` | `normalizeProfile` writes `mediaModel: null` when the field is absent, and the validator's `$defs` require an object. The schema permits omission. | Drop the null key before validating, so the library's contract matches the schema's |
| 4 | **A profile with no `global.style` could not be saved** — same class of bug | `normalizeProfile` fills a missing style with `null`; the validator rejects a non-string; and the engine's `resolveSettings` would copy the null straight into the size sampler | Drop the null style in `save` and in `apply`'s settings — the documented "does not force one" contract |
| 5 | Re-importing an exported profile **duplicated the row** | `importText` called `save` with the profile's own id, and `save` treats an existing id as an update — but the import path bypassed the update because it passed the raw candidate | Normalise first, then `save` the normalised profile so the id is honoured consistently |
| 6 | **The profile row's identity was clipped** — name column 62px, meta clipped by 68px at 390px | Three labelled buttons (144px) sat beside the identity in a 232px row, and the identity's flex column had no usable basis | Moved the actions to a full-width row **below** the identity, and gave the identity `flex: 1 1 0` with `min-width: 0` |
| 7 | **Two 260px panels stacked in the same rail.** Entering media mode while the library was open left both visible, because `toggleMediaMode()` (BE-owned) knows nothing about the library panel | The library shim only guarded its own toggle | Wrapped `toggleMediaMode` once (re-entry guarded) so entering media mode retires the library panel and its mode flag |

Defect 2 was the one that mattered: it made the entire panel inert while every
unit test passed, because the tests only exercised the pure core. The browser
probe is what caught it. Defect 7 was caught by the rail-toggle probe, not by
the library probe.

## 7. Hand-off notes for BE

- **Not wired into `controls.js` / `app.js`.** The host shim
  (`style-library-host.js`) is the sanctioned `media-host.js` pattern; the
  ThinkPad can fold `attachStyleLibrary(app)` into `App._init()` and delete the
  shim later. Nothing else depends on it.
- **`engine.generate({ profile })` is used as-is.** The shim passes the profile
  object explicitly (not only via settings) so the engine's own `opts.profile`
  branch and its seed are honoured. No engine change requested.
- ⚠ **The engine's `resolveSettings` copies a `null` style straight through.**
  `profileToSettings` emits `style: null` for a profile with no style, and
  `resolveSettings` (generator.js) copies it verbatim — `chooseSize` would then
  read `s.strokeSize.min` on a null style. The library drops the key before
  handing settings over, so the shipped path is safe. If any other caller uses
  `profileToSettings` directly, it needs the same guard. Not fixed here:
  `generator.js` is BE-owned.
- **`normalizeProfile` is not idempotent for a missing `mediaModel`** — it
  writes `null` on the first pass and `null` again on the second, so it is
  idempotent in the trivial sense, but a consumer that validates the normalised
  object will reject it. The library works around it (defect 3). BE may want to
  make `normalizeProfile` omit the key rather than write `null`.
- `tests/style-library.test.js` asserts against the **live** schema, so a
  schema change will fail loudly here rather than silently corrupting a save.

- **The exit criteria are met and measured**, not asserted: schema-valid save
  (engine validator), apply changes the render (pixel hash), identical re-bake
  (byte-identical), export→import byte-identical, every control addressable.
- **Vision review of the panel screenshots was NOT completed** — the vision
  backend returned HTTP 429 (rate limit) on three attempts spanning ~7 minutes.
  The geometry measurements above are real DOM numbers, not a visual pass. A
  vision pass should be run before this is called visually done.
- The panel has **no keyboard shortcut** for apply/export beyond Tab+Enter on
  the native buttons; that is a gap against the a11y bar and belongs to M13.
