## 1. Goal

Milestone **R1** (`CLEANROOM.md` §4): *optimiser core — residual/error-driven
stroke placement + per-stroke local refinement (our own hill-climb), on the
modular engine. Beats R0 baseline.*

## 2. What was built

New module **`js/engine/optimizer.js`** (clean-room, written from the SBR
literature — Hertzmann 1998 — **not** from the Code Painter port). It replaces
the modular pipeline's *scatter-random-candidates-then-greedily-pick* approach
(which produced huge random strokes sweeping the canvas — the R0 defect) with:

1. **Residual / error-driven placement.** The painter keeps a live per-pixel
   error map against the target and draws each stroke's anchor from the
   high-error set using a *seeded weighted sample* (not the argmax, which walks
   a single boundary). Paint goes where it is needed.
2. **Per-stroke local hill-climb.** Before committing, a coordinate-ascent
   search nudges position, size, rotation and colour and keeps whichever change
   lowers the local error.
3. **Honest objective.** Every candidate is scored by the signed error delta
   `D = Σ(new − current)` over its own footprint. `D` is invariant to the window
   extent, so a candidate can neither "win" by shrinking its evaluation window
   nor by dragging the dab off-image — the exact failure mode the first draft
   hit (dabs grew to ~70 px and wandered off-canvas). The dab is further clamped
   to a small size band and a small drift radius so the search stays a *dab*.
4. **Local colour sampling.** A dab takes the target colour from a *small core*
   at the anchor, not its whole footprint — averaging a footprint that straddles
   an edge produced a muddy colour that *created* error instead of removing it.
5. **Structure-aware dabs.** Round by default; elongated and oriented along the
   structure-tensor tangent where coherence is high (edges), reusing
   `analyzer.computeStructureTensor` (Phase 1.2).

The optimiser runs on plain pixel buffers (no canvas / DOM), so it is
deterministic and unit-testable under plain `node`. A stroke is a filled,
anti-aliased ellipse whose `color0 === color1`, so the search objective and any
supporting renderer agree.

The parity harness (`tests/parity/harness.html`) now drives the `modular` engine
through the optimiser; `scripts/parity-bench.cjs` records the numbers.

## 5. Honest assessment / next

R1 nails coverage and colour (SSIM roughly doubles) but the render is still
**soft**: dabs are smooth ellipses, so hard edges read as mush (visible in the
composite). That is exactly what **R2 (structure-guided multi-scale)** is for —
coarse→fine passes so fine, edge-aligned strokes sharpen contours — followed by
**R3 (CCL + PCA init)** for stroke-shaped primitives. The optimiser is the
substrate those milestones build on.
