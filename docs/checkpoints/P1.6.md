# P1.6/P1.1 — Brush media and water/ink unification

**Stream:** M3 · **Owner:** Mac/FE (Hermes) · **Date:** 2026-11-11
**Modules:** `js/engine/brush-stamp-engine.js` (rewritten), `js/engine/brush-media.js` (NEW)
**Styles wired:** `ink`, `wash`, `sumi`, `pastel`, `gouache`, `pen`, `knife`, `linocut`

---

## 1. Research — what "the vendored p5.brush integration" actually is

`js/vendor/brush.esm.js` (77 KB, MIT, Alejandro Campos Uribe) is the **modern
p5.brush build**. Its public surface is a *drawing API*:

```
initStandaloneRuntime()  load(canvas)  add(name, params)  set(name, color, weight)
seed(n)  beginStroke(type, ...)  move(x,y)  line(x,y)  endStroke()  render()
hatch()  wash()  fill()  mass()  field()
```

It is **WebGL2-only**. `load(target)` calls
`target.getContext('webgl2', { preserveDrawingBuffer: true })` and throws
`brush.load(target) requires a canvas with a WebGL2 context` otherwise.

The shipped adapter (`brush-stamp-engine.js`) and its helper
(`brush-adapter.js`) both targeted the **old internal API** —
`brush.h({...})`, `brush.f({...})`, `brush.u = {...}`, `brush.b = {...}` — none
of which exist in this build. The first call threw
`TypeError: brush.h is not a function`.

**Consequence: the enhanced stamp path has never run.** `initBrushEngine()`
always failed, `_ready` stayed false, and every style silently used its canvas
fallback. `pencil.js` and `charcoal.js` (the only two styles wired at the time)
were therefore rendering through their fallback paths in production.

## 2. Design

### 2.1 Rewrite against the real API

`brush-stamp-engine.js` was rewritten to:

1. create a **dedicated WebGL2 canvas** (never touched by `getContext('2d')` —
   a canvas hands out exactly one context type, and a 2D context permanently
   blocks the WebGL2 request),
2. `initStandaloneRuntime()` → `load(canvas)`,
3. `set(brushName, color, size)` to select tip + colour + weight,
4. `beginStroke('curve'|'segments', …)` → `move()` → `line()` → `endStroke()`,
5. `render()` to composite the brush mask onto the target,
6. `drawImage` the WebGL canvas onto the caller's 2D canvas — the same
   pattern `js/engine/relief.js` already uses.

### 2.2 Shared media parameters (`brush-media.js`, Phase 1.6)

Watercolor, ink, wash, sumi, pastel, gouache, pen and knife each carried their
own independently-named parameter set. `brush-media.js` is now the single
source of truth:

- `MEDIA_PARAMS` — the schema: `size`, `spacing`, `scatter`, `sharpness`,
  `grain`, `pressure`, plus the water/ink-specific `bleed`, `bleedOpacity`,
  `tideDarken`, `granulation`, `granulationCount`.
- `MEDIA_PRESETS` — per-style overrides naming a real p5.brush tip.
- `resolveMedia(name)` fills unspecified fields from the schema defaults, so
  adopting a preset is **output-neutral** until a caller opts in.
- `toStampOptions(media, extra)` maps onto `stampStrokeSync`.
- `isKnownBrushName(name)` lets a style fall back instead of throwing.

### 2.3 Wiring the styles

Each style's `render()` now tries the enhanced path first and falls through:

```js
if (isBrushReady() && shape.type === 'S') {
  const media = resolveMedia('ink');
  if (isKnownBrushName(media.brushName)) {
    const ok = stampStrokeSync(ctx, shape, toStampOptions(media, {
      color: stampColor(shape), alpha: o, size: shape.params[6], progress,
    }));
    if (ok) return;
  }
}
// … existing custom renderer
```

`pencil.js` and `charcoal.js` were already wired and were left alone apart from
the engine fix (they are ThinkPad-owned files; see §4).

## 4. Bugs found and fixed

### 4.1 `brush.h is not a function` — the whole path was dead
Fixed by the rewrite (§2.1). **This was the biggest finding of the stream.**

### 4.2 `brush.add()` on an existing tip breaks every later stroke
`add(name, params)` **overwrites** the tip's registered param object. A param
without a `type` field makes every subsequent stroke throw
`Cannot read properties of undefined (reading 'type')`. The vendor exports no
brush list, so there is no safe way to detect built-in tips — the only safe
policy is **never to call `add()` for a shipped tip**. `BRUSH_OVERRIDES` is
therefore empty, with a comment explaining why.

### 4.3 `brush.clear()` paints the target opaque
The vendored `clear()` is a canvas *background*, not a transparent wipe: it
filled the whole offscreen target, which then covered the caller's canvas when
composited. Fixed by clearing the GL backbuffer directly
(`clearColor(0,0,0,0)` + `clear(COLOR_BUFFER_BIT)`).

### 4.4 Presets named non-existent brush tips
`MEDIA_PRESETS` originally named `round`, `flat` and `pencil` — none of which
exist. Remapped to real tips (`HB`, `marker`, `cpencil`) and added
`isKnownBrushName()` so a bad preset falls back instead of throwing.

### 4.5 `opts.size` could arrive as an object
`resolveMedia()` returns `size` as a `{min,max,default}` schema object; passing
that straight to the brush made the weight `NaN`. `stampStrokeSync` now unwraps
it.

### 4.6 Pre-existing: `pencil.js` passes `brushName: 'pencil'`
That tip does not exist (it is `cpencil`), so pencil has always silently used
its fallback. `pencil.js` is **ThinkPad-owned and dirty**, so it was **not
edited** — reported in AGENTS.md §0.
