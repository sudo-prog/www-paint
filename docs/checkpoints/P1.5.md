# P1.5 — Lightweight smudge / blend + optional height buffer

**Date:** 2026-11-12 · Agent: BE (ThinkPad) · **Status: done** · Stream **B1**
(`HANDOFF-BE.md`) · Roadmap Phase 1.5 · closes Phase 1

---

## 1. Goal

Phase 1.5: a *lightweight* smudge/blend and an optional paper-height buffer, in
the renderer spine (`renderer.js`). Both opt-in so the pinned baselines stand.

## 2. Design

- **Smudge** — `Renderer.setSmudge(amount)` (0..1, default 0). When set,
  `renderAll` applies `_applySmudge(ctx, w, h, amount)` once per pass: a
  deterministic 3×3 blend (each pixel nudged `k = amount·0.25` toward the mean of
  its four neighbours). No RNG — same input, same output.
- **Height buffer** — `Renderer.getHeightBuffer()` returns the wet sim's
  `paperHeight` `Float32Array` (the sheet relief the wet media sits on), or
  `null` when wet media is off. `engine.getHeightBuffer()` passes it through.
  Shading/export consumers can read relief from it rather than re-deriving it.

## 3. Evidence

- `scripts/wet-media-probe.cjs` — smudge changes output and is deterministic
  (two renders byte-identical); the height buffer is a 160×160 `Float32Array`
  when wet media is on and `null` when off.
- `node scripts/visual-regression.cjs` → **pass=9 fail=0 error=0** — smudge
  defaults off, so nothing re-baselines.
- `node tests/engine.test.js` → **105/105**.

## 4. Files

- `js/engine/renderer.js` — `setSmudge` / `_applySmudge` / `getHeightBuffer`
- `js/engine/engine.js` — `setSmudge` / `getHeightBuffer` passthroughs
- `docs/checkpoints/P3.3.md` — the companion note (wet media)

## 5. Honest scope

The smudge is an isotropic blend, not a directional, stroke-following drag; a
true smudge brush (drag pigment along the stroke/pressure direction) is future
work. The height buffer is exposed and consumed by the wet pass; a full
height→shading export is downstream.
