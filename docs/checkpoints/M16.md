## 2. The one defect found & fixed during verification

The shell's global `.slider-row` is deliberately collapsed to a **~10px band**
(its 44px input overhangs via negative margins) so the Brush panel stays compact
(M13). Reusing it for six **labelled** rows made them pile up — each row's
labelled content overflowed ~46px and every label overlapped the next.

Fixed with a **scoped** override (§16): `height:auto; min-height:0;
margin:0 0 var(--space-1)`, `label{display:block}`, `input[type=range]{margin:0}`
— restores the natural row height while the input keeps its 44px target (only the
row's layout box changes).

This class of bug is **invisible to the a11y sweep** (it measures target size, not
layout), so the probe asserts it directly — per row `getBoundingClientRect()
.height >= 44` **and** `scrollHeight - clientHeight === 0`. The guard is verified
**both ways**: broken → FAIL, fixed → PASS, via the probe's `PMX_BROKEN_ROW=1`
self-test hook (the SAME binary is red on the broken layout and green on the fix).
